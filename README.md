# Garmin Raw Archive — Google Apps Script

אפליקציה קטנה לשמירת תשובות מקור מ־Garmin ב־Google Drive, עם סנכרון שניתן להמשיך וממשק קריאה לצ׳אטים. הנתונים והמפתחות אינם נשמרים ב־Git.

## מה כבר ממומש

- HTML בעברית, RTL, המאפשר צפייה במצב הסנכרון, עיון ברשומות והורדת JSON מקורי.
- חיבור ל־Personal API, כולל קבלת JWT כטקסט רגיל ורענון הרשאה במקרה של 401.
- שמירת טקסט תשובת המקור ללא שינוי, SHA-256, זמן המשיכה, הנתיב והתקופה.
- שמירת גרסה נוספת כשנתוני המקור משתנים; אין יצירה נוספת לתשובה זהה.
- סריקת ההיסטוריה עד `HISTORY_START`, ברירת מחדל 2000-01-01. זו תחילת הסריקה, לא טענה שקיימים נתונים מאז.
- השלמת כל דפי הפעילויות עד קבלת דף ריק, פרטי הפעילות ותוכנית האימון. אפשר להפעיל גם שמירת ZIP המקורי של פעילות (`INCLUDE_FIT=true`).
- טווחי תאריכים: סיכומים יומיים, צעדים, סטרס, שתייה, משקל ויעדים, סיכומי שינה ו־HRV, ‏Body Battery ופעילות יומית.
- לכל יום נסרק: דופק מפורט, שינה, HRV, סטורציה, יומן מזון וגיל כושר — כולל ימים שסיכומם ריק, כדי לא לדלג על נתון קיים.
- הגדרות פרופיל ואזורי דופק נמשכים מדי יום.
- כל צ׳אט מחובר יכול לבקש המשך סנכרון; קריאה מרעננת כברירת מחדל. המערכת חוזרת שלושה ימים אחורה לקלוט תיקונים מאוחרים.
- נשמרת נקודת התקדמות לכל בקשה. 401/403/404/429 ושגיאות אחרות **אינן** נחשבות לנתונים ריקים: המשימה נעצרת בנקודת הכשל ומוצגת שגיאה.

הכיסוי הוא של קבוצות הנתונים המפורטות בקוד, ככל שה־Personal API מאפשר אותן בחשבון. אין כאן הבטחה שזהה לייצוא החשבון המלא של Garmin, או שכל מדד היסטורי זמין ב־API. ה־API/ההרשאות/הדגם עשויים להגביל נתונים. אם endpoint מחזיר למשל 404 לתקופה ללא מידע, צריך לבדוק את משמעות התשובה לפני שינוי המדיניות; הקוד מעדיף לעצור ולא להסתיר פער.

## הקמה דרך Git ו־clasp

נדרש Node.js גרסה 20 ומעלה וחשבון Google. הכלי `clasp` מפותח במאגר Google ומשמש להעלאת קוד; Git לבדו אינו נותן הרשאה ל־Google.

1. צור מאגר GitHub **פרטי** בשם `garmin-raw-appscript` והעלה את קובצי הפרויקט. אל תעלה נתוני בריאות או מפתחות.
2. הורד/שכפל את הקוד במחשב שלך. הפעל את [Apps Script API](https://script.google.com/home/usersettings).
3. ב־Windows פתח `Setup.cmd`. לחלופין: `npm ci --ignore-scripts`, ואז `npm run setup`.
4. השלם את הכניסה ל־Google בחלון שייפתח. לא מדביקים סיסמאות או קודי הרשאה בצ׳אט. הסקריפט ייצור פרויקט `Garmin Raw Archive`, יבדוק את הקוד ויעלה אותו.
5. בעורך Google: Project Settings → Script Properties. הוסף:

| שם | ערך |
|---|---|
| `GARMIN_PERSONAL_API_KEY` | מפתח Garmin שלך |
| `API_ACCESS_KEY` | סוד אקראי נפרד, לפחות 32 תווים |
| `HISTORY_START` | אופציונלי: תאריך ההתחלה הידוע; אחרת הסריקה מתחילה ב־2000-01-01 |
| `INCLUDE_FIT` | `true` לשמירת קובצי ZIP/FIT מקוריים של הפעילויות; אחרת JSON בלבד |
| `PAUSED` | `true` לעצירת המשך המשיכה האוטומטי; אינו מונע סנכרון ידני מורשה |

6. הרץ `setup` פעם אחת בעורך ואשר את ההרשאות המוצגות. נדרשת גישה ל־Drive, בקשות רשת ויצירת טריגר המשך. ברירת המחדל היא Drive scope רחב משום שהקוד משתמש ב־DriveApp; אל תאשר אם אינך מעוניין בהרשאה זו. התיקייה והקבצים עצמם נשארים פרטיים.
7. `setup` יוצר תיקייה `Garmin Raw Archive`, קובץ מצב וטריגר המשך כל עשר דקות, עם תקציב עבודה של 25 שניות בכל הרצה. הבקשה האחרונה עשויה להסתיים מעט אחרי תקציב זה. המכסות היומיות של Google עדיין חלות; שגיאות מכסה אינן מוחקות התקדמות. סריקה מלאה של שנים עשויה להימשך זמן רב, במיוחד כשהסריקה מתחילה הרבה לפני השימוש הראשון.
8. Deploy → New deployment → Web app. ברירת המחדל במניפסט היא **רק אתה** (`MYSELF`). מסך הכניסה דורש את `API_ACCESS_KEY`, ולא את מפתח Garmin.

כדי להתחיל מוקדם בלי לחכות לטריגר, היכנס למסך ולחץ סנכרון. לא מסומן שהיסטוריה הושלמה עד ההגעה ל־HISTORY_START. `lastSync` מציין טווח נתונים עדכניים שהושלם, ולא שהושלמה כל ההיסטוריה. נתונים יכולים להתקבל חלקית עד לסיום המשיכה; תמיד בדוק מצב ושגיאות.

## המשך עדכון מ־GitHub

ה־workflow `Check` מפעיל בדיקות ללא סודות. `Push code to Apps Script` מופעל **ידנית** מ־Actions כדי שלא להעלות קוד לחשבון Google לפני הגדרת ההרשאות והפרויקט.

בהגדרות GitHub צור סביבה בשם `apps-script`, ואז שמור Secrets (לא קבצים במאגר):

- `CLASPRC_JSON`: תוכן קובץ ההרשאה המקומי ש־`clasp login` יוצר. זוהי הרשאה רגישה לפרויקטי Apps Script; אין לשלוח בצ׳אט ואין להדפיס בלוגים.
- `APPS_SCRIPT_ID`: ה־Script ID מתוך `.clasp.json` המקומי או Project Settings.

ה־workflow מעלה קוד לפרויקט הייעודי. `clasp push --force` מחליף את מלוא קוד הפרויקט בגרסת המאגר, ולכן אין לכוון אותו לפרויקט עם קוד אחר. הוא **אינו** מפרסם פריסת Web App חדשה ואינו משנה את קהל הגישה. אחרי שינוי קוד בפרויקט שכבר נפרס, עדכן את גרסת הפריסה בממשק Google. אפשר להפוך את ה־workflow לאוטומטי לאחר שהחיבור נבדק.

## גישה מצ׳אטים

צ׳אט צריך יכולת לקרוא API או חיבור MCP. קישור רגיל לצ׳אט אינו מתקין כלי ואינו מאפשר לו להפעיל קוד. לא ניתן להבטיח חיבור לכל שירות צ׳אט.

`scripts/mcp_bridge.py` הוא גשר **MCP מקומי דרך stdio** ללקוחות שתומכים בכך, כמו לקוחות שולחניים תואמים. הוא אינו שרת MCP מרוחק ואינו חיבור מובנה לכל שיחה ב־ChatGPT.

ללקוח חיצוני שמבצע POST בלי התחברות Google נדרשת פריסת Web App שמתירה בקשות אנונימיות ומריצה כבעלים, בעוד הקוד בודק `API_ACCESS_KEY` בכל בקשה. **שינוי כזה דורש החלטה מודעת שלך**: כתובת השירות תהיה נגישה באינטרנט, ומחזיק מפתח הארכיון יוכל לקרוא את נתוני הבריאות ולהפעיל משיכה. תיקיית Drive אינה משותפת. אל תהפוך את הקבצים עצמם לציבוריים.

הקוד נמסר עם `MYSELF`; כל עוד לא שינית גישה, הגשר לא יפעל כלקוח חיצוני. אם בחרת לאפשר גישה חיצונית: שנה במניפסט את `webapp.access` ל־`ANYONE_ANONYMOUS`, העלה ופרוס בהתאם להגבלות חשבון Google שלך. בחשבונות מנוהלים מנהל הארגון עלול למנוע זאת.

דוגמת תצורת לקוח MCP מקומי (להחליף את המיקום, הכתובת והמפתח רק בהגדרות המקומיות):

```json
{
  "mcpServers": {
    "garmin": {
      "command": "python",
      "args": ["C:/garmin-raw-appscript/scripts/mcp_bridge.py"],
      "env": {
        "GARMIN_ARCHIVE_URL": "https://script.google.com/macros/s/YOUR_DEPLOYMENT/exec",
        "GARMIN_ARCHIVE_ACCESS_KEY": "YOUR_SEPARATE_ARCHIVE_ACCESS_KEY"
      }
    }
  }
}
```

לגשר ארבעה כלים: `garmin_status`, ‏`garmin_sync`, ‏`garmin_list`, ‏`garmin_get`.

אפשר גם לפנות ב־POST ישיר בגוף JSON:

```json
{
  "accessKey": "YOUR_SEPARATE_ARCHIVE_ACCESS_KEY",
  "action": "get",
  "params": {
    "dataset": "daily",
    "start": "2026-10-01",
    "end": "2026-10-29",
    "limit": 5,
    "offset": 0,
    "sync": true
  }
}
```

המפתח אינו מועבר בכתובת URL. Apps Script אינו מספק לקוד גישה לכותרת Authorization של בקשה נכנסת, ולכן API זה משתמש בסוד בגוף הבקשה. ContentService מחזיר הפניה ל־Google; הלקוח חייב לתמוך בה. גם שגיאות יישומיות מוחזרות בדרך כלל ב־HTTP 200, ויש לבדוק את `ok` ואת `error`.

קובצי טווח מוחזרים בשלמותם; הסינון מחפש **חפיפה**, אינו חותך את תשובת המקור. יש לבדוק `nextOffset` ולסנן את הרשומות בפנים לפי השאלה. `raw` מכיל את הטקסט המקורי, ו־`data` הוא הפענוח שלו. FIT ZIP נשמר ב־Drive ואינו מוזרם דרך גשר ה־JSON.

## בדיקות ומגבלות אימות

`npm test` בודק הרשאות, JWT כטקסט, שימור תשובה ודדופליקציה, המשך לאחר כשל, חפיפת סנכרון, דפדוף פעילויות, סינון וחלוקה לעמודים, והשלמת היסטוריה. הבדיקות מדמות את שירותי Google ו־Garmin; הן אינן מהוות הוכחה שהפרויקט כבר הותקן/נפרס בחשבון Google. נדרש smoke test אמיתי אחרי ההרשאה והפריסה.

התיעוד שעליו מבוססים הנתיבים: [Garmin Personal API Python](https://github.com/garmin/connect-personal-api-python), ‏[Google clasp](https://github.com/google/clasp), ‏[Apps Script quotas](https://developers.google.com/apps-script/guides/services/quotas).
